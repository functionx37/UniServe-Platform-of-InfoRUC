# 管理员维护学生党团进度 - 前端对接文档

本文档用于和负责管理后台前端的同学交接“管理员登记/修改学生党团进度”功能。

后端已完成，统一返回格式仍然是：

```json
{
  "success": true,
  "message": "操作成功",
  "data": {}
}
```

## 1. 鉴权与权限

- 所有接口都在 `/admin/party/*`
- 请求头需要带：

```http
Authorization: Bearer <token>
```

- 只有角色 `1-学院领导`、`2-管理老师` 可以调用
- 角色 `3-骨干` 会被拒绝访问

## 2. 功能范围

本次后端提供了 5 个接口：

1. 查询党团阶段字典
2. 查询学生党团进度列表
3. 查询单个学生党团进度详情
4. 保存单个学生党团进度
5. 批量导入党团进度

建议前端页面形态：

1. 左侧或顶部：学生筛选和列表
2. 右侧：当前学生的阶段明细编辑区
3. 编辑完成后点击“保存”
4. 批量导入可以保留现有导入页，直接继续调用导入接口

## 3. 查询阶段字典

### `GET /admin/party/stages`

用途：

- 获取标准党团流程阶段
- 前端可用于渲染表头、阶段顺序、说明文案

返回示例：

```json
{
  "success": true,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "stageOrder": 1,
      "title": "提交入党申请书",
      "description": "提交申请书并完成信息登记",
      "defaultTime": "2026-03-12",
      "status": "active"
    }
  ]
}
```

字段说明：

- `id`: 阶段 ID，保存时要回传
- `stageOrder`: 阶段顺序
- `title`: 阶段标题
- `description`: 阶段说明
- `defaultTime`: 默认展示时间
- `status`: 当前阶段配置状态，现阶段前端可直接展示或忽略

## 4. 查询学生进度列表

### `GET /admin/party/students`

查询参数：

- `grade` 可选
- `major` 可选
- `keyword` 可选，支持按 `学号 / 姓名 / 用户名` 模糊搜索

示例：

```http
GET /admin/party/students?grade=2026&keyword=张三
```

返回示例：

```json
{
  "success": true,
  "message": "操作成功",
  "data": [
    {
      "userId": 101,
      "studentNo": "20260001",
      "realName": "张三",
      "grade": "2026",
      "major": "信息学院",
      "identity": "普通学生",
      "currentStage": "确定入党积极分子",
      "progressPercent": 20,
      "completedStageCount": 1,
      "totalStageCount": 5
    }
  ]
}
```

字段说明：

- `userId`: 学生用户 ID，详情和保存接口都要用它
- `currentStage`: 当前阶段名称
- `progressPercent`: 进度百分比
- `completedStageCount`: 已完成阶段数
- `totalStageCount`: 总阶段数

前端建议：

- 列表项主标题显示 `realName + studentNo`
- 次信息显示 `grade / major`
- 右侧可显示 `currentStage` 和 `progressPercent`


字段说明：

- `stages`: 更适合做表单编辑
- `completedAt`: 格式固定为 `yyyy-MM-dd HH:mm:ss`，未完成时为 `null`
- `notes`: 管理员备注

前端建议：

1. 编辑表单建议以 `stages` 数组为主
2. 预览时间线建议用 `nodes`
3. 每一行至少提供：
   - 完成开关 `completed`
   - 完成时间 `completedAt`
   - 备注 `notes`

## 6. 保存单个学生进度

### `PUT /admin/party/students/{userId}`

用途：

- 管理员保存当前学生的党团进度
- 支持一次提交多个阶段
- 只会更新你传入的那些阶段，不会覆盖没传的阶段

请求体示例：

```json
{
  "stages": [
    {
      "stageId": 1,
      "completed": true,
      "completedAt": "2026-06-10 15:30:00",
      "notes": "材料已核验"
    },
    {
      "stageId": 2,
      "completed": false,
      "completedAt": null,
      "notes": "等待组织考察"
    }
  ]
}
```

请求字段说明：

- `stageId`: 必填，对应阶段字典里的 `id`
- `completed`: 可选，不传时后端默认按 `true` 处理，不建议省略
- `completedAt`: 可选
- `notes`: 可选

保存规则：

- `completed = true`
  - 如果传了 `completedAt`，后端使用前端传入值
  - 如果没传，后端自动写入当前时间
- `completed = false`
  - 后端会把该阶段的 `completedAt` 清空
- `notes`
  - 传了就更新
  - 可传空字符串清空备注

返回：

- 返回值就是“最新详情”，结构与 `GET /admin/party/students/{userId}` 完全一致
- 前端保存成功后可直接用返回结果刷新右侧详情，不需要再发一次详情请求

## 7. 批量导入党团进度

### `POST /admin/party/import?fileName=party_progress.xlsx`

说明：

- 当前接口仍然使用“前端先解析 Excel/CSV，再把 JSON 数组传给后端”的方式
- 与现有 [admin-frontend/src/PartyProgressImport.tsx](/home/leory/codes/UniServe-Platform-of-InfoRUC/admin-frontend/src/PartyProgressImport.tsx) 兼容

请求体示例：

```json
[
  {
    "studentNo": "20260001",
    "stageTitle": "提交入党申请书",
    "completed": true,
    "notes": "导入完成"
  }
]
```

返回示例：

```json
{
  "success": true,
  "message": "已导入 1 行，失败 0 行",
  "data": {
    "importSession": {
      "id": "partyimp-001",
      "fileName": "party_progress.xlsx",
      "totalRows": 1,
      "successRows": 1,
      "failedRows": 0,
      "importedAt": "2026-06-11 17:00:00"
    },
    "errors": [],
    "message": "已导入 1 行，失败 0 行"
  }
}
```

导入字段说明：

- `studentNo`: 必填
- `stageTitle`: 必填，必须与阶段字典中的 `title` 一致
- `completed`: 可选，缺省时后端按 `true` 处理
- `notes`: 可选

## 8. 与学生端的联动

这次后端改完后，管理员保存的数据会直接影响学生端：

- 学生小程序 `GET /party/progress`
- 已完成阶段会显示管理员登记的 `completedAt`
- 当前阶段会按“第一个未完成阶段”自动计算
- 如果全部阶段都完成，学生端会显示 `已完成全部阶段`

这意味着：

- 管理后台无需再额外调学生端接口验证
- 保存成功后，学生重新打开党团页面就能看到最新进度

## 9. 前端对接顺序建议

建议按这个顺序接：

1. 先接 `GET /admin/party/stages`
2. 再接 `GET /admin/party/students`
3. 点击学生后接 `GET /admin/party/students/{userId}`
4. 编辑后接 `PUT /admin/party/students/{userId}`
5. 最后保留或接入 `POST /admin/party/import`

## 10. 建议在 `adminApi.ts` 增加的方法

建议新增下面几个方法：

```ts
async listPartyStages() {
  return request<any[]>('/admin/party/stages')
}

async listPartyStudents(query: { grade?: string; major?: string; keyword?: string }) {
  const params = new URLSearchParams()
  if (query.grade) params.append('grade', query.grade)
  if (query.major) params.append('major', query.major)
  if (query.keyword) params.append('keyword', query.keyword)
  return request<any[]>(`/admin/party/students?${params.toString()}`)
}

async getPartyStudentDetail(userId: number) {
  return request<any>(`/admin/party/students/${userId}`)
}

async savePartyStudentProgress(userId: number, payload: {
  stages: Array<{
    stageId: number
    completed: boolean
    completedAt?: string | null
    notes?: string
  }>
}) {
  return request<any>(`/admin/party/students/${userId}`, {
    method: 'PUT',
    body: payload,
  })
}
```

现有导入方法保留即可：

```ts
async importPartyProgress(fileName: string, rows: any[]) {
  return request<ImportPartyProgressResult>(`/admin/party/import?fileName=${encodeURIComponent(fileName)}`, {
    method: 'POST',
    body: rows,
  })
}
```

## 11. 联调时的注意事项

- `userId` 和 `stageId` 都要用后端返回值，不要前端自己猜
- `completedAt` 必须传 `yyyy-MM-dd HH:mm:ss`，不要传 ISO 字符串
- 如果页面里用了日期时间选择器，提交前记得格式化
- 保存接口返回的就是最新详情，建议直接用返回数据覆盖本地状态
