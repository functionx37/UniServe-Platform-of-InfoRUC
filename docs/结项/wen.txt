第1页 · 封面

各位老师、同学大家好。

我们第五小组本次软件工程大作业的项目名称是：

UniServe——人大信息学院学生综合服务与党团管理平台。

本项目面向信息学院学生和学院管理人员，目标是构建一个集学生事务办理、党团流程管理、信息通知以及学业分析于一体的综合服务平台。

下面由我进行项目汇报。

第4页 · 项目阶段时间线

我们的项目整体分为三个阶段推进。

第一阶段是需求分析与软件设计阶段。

在这一阶段，我们完成了用户需求梳理、功能规划以及系统架构设计。

第二阶段是代码实现与测试阶段。

第5页 · 需求分析

在需求分析阶段，我们首先明确系统的用户对象。

主要分为两类：

第一类是学生用户。

学生需要通过系统完成事务申请、通知查看、党团进度查询以及学业情况分析等操作。

第二类是管理员用户。

管理员负责信息维护、审批处理以及资源管理。

围绕这些需求，我们编写了软件需求规格说明书，对系统功能进行了系统化整理。


第6页 · 功能清单

在需求分析基础上，我们进一步拆分出了具体功能模块。

例如：

智能问答与政策知识库模块，可以帮助学生快速查询相关政策信息；

党团事务流程管理模块，可以展示学生当前流程状态；

信息集成与精准推送模块，可以实现学院信息通知；

此外还包括电子证明生成、审批流程以及学业分析预警等功能。

通过功能拆分，我们将用户需求转化为了具体的软件功能。


第7页 · 软件设计阶段

在软件设计阶段，我们完成了系统整体架构设计。

系统采用前后端分离架构。

学生端采用微信小程序作为主要入口，满足学生移动端使用需求；

管理员端采用 Web 平台，方便进行复杂业务管理；

后端负责统一处理业务逻辑，并通过 API 与前端交互。

同时，我们通过接口文档和 UML 建模提前明确系统结构，为后续开发提供基础。



第8页 · 代码实现与测试阶段协作

进入开发阶段后，我们进行了团队分工。

成员 A、B 主要负责后端开发；

成员 C 负责微信小程序端维护；

成员 D 负责管理后台、测试文档整理以及项目整合。

开发过程中，我们使用 GitHub 进行版本管理。

通过提交记录，我们能够追踪功能迭代过程，同时也逐渐形成了较规范的协作流程。



第9页 · 项目与功能概述分隔页

下面进入第二部分：

项目与功能概述。

这一部分主要介绍系统整体架构、学生端功能以及管理后台功能。


第10页 · 系统架构与部署方式

我们的系统采用三端分离架构。

整体代码规模约为 15777 行。

其中：

后端采用 Java Spring Boot 实现，是整个系统业务逻辑核心；

学生端采用微信小程序开发；

管理后台采用 React + TypeScript 开发。

三个部分通过 RESTful API 进行通信。

同时，我们设计了统一请求层，并支持 Mock 模式，使前端可以在后端开发过程中独立调试。


第11页 · 学生端功能总览

学生端微信小程序是学生使用系统的主要入口。

目前实现了九个主要功能模块：

包括登录与会话管理；

首页待办汇总；

智能问答；

党团流程查询；

事务申请；

成绩单上传和学业分析；

通知公告；

模板下载；

个人中心。

底部 TabBar 设置首页、智能问答、事务申请和个人中心四个一级入口，提高使用便利性。


第12页 · 管理后台功能

管理后台主要服务学院管理人员。

主要功能包括：

事务审批；

公告发布；

模板管理；

后台数据维护。

通过管理后台，管理员可以完成信息维护和业务处理，并与学生端形成完整业务闭环。

同时，我们整理了用户手册、API 文档以及 Postman 测试集合，方便项目交付和后续维护。


第13页 · 学业分析功能开发

下面以学业分析模块为例介绍具体开发过程。

该模块主要包含三个页面：

学业概览页面；

成绩单上传页面；

分析结果页面。

学生上传成绩数据后，系统会展示学分完成情况，并提供一定的选课建议。

这个模块体现了前端交互、后端接口以及数据展示的结合。


第14页 · 学业分析实现细节

具体实现过程中：

首先，我们在 Service 层设计上传和分析接口，并使用 Mock 数据完成前期开发。

上传页面实现了文件格式和大小校验。

分析结果页面通过组件展示学分进度以及分析建议。

在开发过程中，我们使用 AI agent 辅助生成部分页面结构和重复代码。

之后由人工完成接口对接、逻辑调整以及交互优化。



第15页 · 测试策略与缺陷修复

测试阶段，我们主要采用人工测试方式。

我们针对核心业务流程进行了完整验证，主要功能均可以正常运行。

同时，在异常测试过程中，我们发现：

管理员导入 Excel 名单时，如果输入错误年级或者不存在专业，系统可能仍然接受。

针对这个问题，我们在后端加入白名单校验和正则表达式限制。

最终修复了这一数据安全问题。

认识与反思。

第17页 · 协作中遇到的问题

整个开发过程中，我们主要遇到了两个问题。

第一个是 Git 协作问题。

多人同时修改代码时，会产生分支合并和冲突。

第二个是 AI agent 使用限制。

随着项目代码量增加，AI 工具额度不足影响部分开发进度。

最终，我们通过明确模块边界、规范提交方式解决了这些问题。


第18页 · 对大模型与软件工程的新认识

通过这次项目实践，我们认识到：

AI agent 确实能够提高开发效率。

例如：

生成页面框架；

生成 Mock 数据；

辅助代码编写。

但是 AI 不能替代工程判断。

系统架构设计、模块划分以及代码质量控制仍然需要开发者完成。

所以我们认为：

Agent 是工具，不是队友。

同时，团队协作和规范管理同样是软件工程的重要部分。
